Causa Tecnica Identificata:

In Composizione.hashCode() il calcolo restituisce id != null ? id.hashCode() : 0. Nel controller di checkout (CreazioneOrdineController#post), le istanze sono appena create con id == null. Tutte le righe generano lo stesso hash code 0 e finiscono nell'identico bucket dell'HashSet. Dato che equals restituisce false per entità transienti, ogni inserimento scorre tutti gli elementi precedenti eseguendo N(N-1)/2 confronti a vuoto.

Piano di Ottimizzazione Consigliato

Priorità Componente Sintomo / Problema Azione Risolutiva
P1 - Alta CreazioneOrdineController Inserimento transienti in HashSet causa $O(N^2)$ (88.7x più lento) Usare List<Composizione> durante il checkout prima del salvataggio.
P2 - Media SessionCarrello#getRealCarrello Ciclo N+1 query singole findById Riscrivere con prodottoDao.findAllById(ids) (1 singola query SQL).
P3 - Media Prodotto (@Data Lombok) Lookup mappa 20x più lenta a causa di hash su stringhe e blob immagine Usare @EqualsAndHashCode(onlyExplicitlyIncluded = true) sul solo ID.
P4 - Bassa EncryptorUtil & Form Tempi ottimali (< 6 µs) Nessuna modifica necessaria.
